  Why: CPMamba's sequence is <= 100 cycle summaries (eval is prefixes 1..100) -- too short for Mamba to matter.
  Long Mamba runs over raw points: per cycle 3 channels (V/max, I in C, Q/nominal) x 300 points (150 charge + 150
  discharge), cycles end to end = ~30k steps for 100 cycles. Linear(3->d_model), Mamba stack, output CLS at the end.
  --long_boundary none | shared (one learned token before every cycle) | index (nn.Embedding(100,d), token k before
  cycle k); only the final position has the output token.
  Chemistry: --long_chem_cls 1 (per-chemistry CLS), --long_chem_boundary 1 (per-chem start token: replaces shared token,
  or ADDED to index token: index[k]+chem[c]); independent. qsub CHEM_CLS / CHEM_BOUNDARY. Not queued yet.
  Pooled loader, prefixes 1..100 (same data as CPMLP), batch 8 x accum 4. ~900M sequence steps / epoch -> may be slow;
  test_longmamba.py --gpu prints time/memory per batch size. Every-cycle readout is the fix if too slow.
