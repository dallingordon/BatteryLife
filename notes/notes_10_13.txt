--- Idea: hierarchical "simulator" (later) ---
Inner SSM over points of one cycle: input = controls (protocol current / phase / dt), output = voltage response,
  initial state from the outer model. Run in simulation mode (no observed V as input) -> parallel, no point-level
  teacher forcing. For diagonal LTI S4D the initial-state response is closed form: y_t = 2 Re(sum_n C_n exp(A_n tau_t) x0_n).
Outer SSM over cycles: input z_k (encoded observed cycle) + cycle-level controls, h_k -> inner init for k+1,
  capacity head, z_{k+1} prediction. Roll out from cycle 100 until capacity < 0.8 -> EOL.
Notes:
  - Input-free LTI rollout (h_{k+1} = A h_k) can only decay -> no knee. Need closed loop through nonlinearity
    (feed predicted z back). LTI shared dynamics + nonlinear feedback.
  - Teacher forcing: TF over all cycles (parallel) + latent AR (predict z_{k+1}, feed back) + multi-step rollout loss
    from random k0 (mostly near 100), curriculum on horizon. Scheduled sampling = weaker fallback.
  - CV phase: voltage is controlled, current is the response; discharge ends at V cutoff -> the real input is the
    protocol, not the measured trace (measured trace length leaks capacity).
  - Check first: does "first cycle with discharge cap < 0.8 x nominal" in the cache reproduce the label JSONs?
  - Data now: 300 points resampled by RECORD INDEX (150 charge + 150 discharge), time_in_s dropped,
    V normalized by the cycle's own max V (hides resistance growth), I in C-rate, Q / nominal. Rests (|I| < 0.01C) dropped.
Decided: do explicit dt in the current S4D / Mamba setups FIRST (one-variable test on the 0.203 / 0.267 baselines).

--- Explicit dt plan ---
Cache: interpolate time_in_s at the resampled points, store dt as a 4th channel. Global unit (not per cycle/cell).
  Normalize tau = dt / c, c = one global constant (median within-segment dt over Li-ion train cells, from stats pass).
  Any constant c is absorbed by the learned log_dt; c only sets the init range / numerics. With tau == 1 the model
  reduces exactly to the current one (built-in control). Clip tau at a high percentile if the tail is extreme (stats pass).
  Same c for all chemistries later so rates stay comparable.
Rests: v1 leaves them out (boundary steps get typical dt). Thinking: a REST TOKEN at boundaries carrying the rest
  duration (decay by exp(A * tau_rest), input term kept normal size). Not decided.
S4D: scan backend only (FFT needs constant step). delta[b,e,t] = exp(log_dt[e]) * tau[b,t]. Drop exact-ZOH B fold,
  use kernel's delta*B*u (same as Mamba). Test vs exact variable-dt recurrence.

  Unfused path. log_dt no weight decay (same tagging as S4D).

--- LAST: "simulation-generative" life prediction (idea, not built) ---
Instead of regressing EOL directly, learn a simulator of the cell and run it forward until capacity < 80%.
  Inner model (points within one cycle): INPUT = current profile (the protocol: C-rate, phase CC/CV/rest) + dt,
    OUTPUT = voltage response. Initial state comes from the outer model. Run in "simulation mode" (no observed V fed
    back) -> one parallel scan per cycle, no point-level teacher forcing needed.
  Outer model (one step per cycle): input = encoded cycle k (+ cycle-level controls: protocol, rest / calendar time),
    state h_k -> initial state of cycle k+1's inner model (+ direct capacity head as a sanity check / fallback).
  Capacity of a simulated cycle = integral of current over time, Q = sum_t |I_t| * dt_t, over the discharge, stopped
    when the simulated voltage hits the cutoff (that is how the tester ends discharge). Needs the real dt (-> the
    explicit-dt work above is the prerequisite).
  Prediction: observe cycles 1..100 (teacher forced), then roll the outer model forward cycle by cycle; predicted EOL =
    first cycle whose Q / nominal < 0.8.
Training / teacher forcing:
  - Teacher forcing over ALL cycles (incl. past 100 -> uses the thrown-away late-life data): observed cycles 1..k -> predict
    cycle k+1, all k in parallel.
  - Exposure bias in the rollout: latent autoregression (outer predicts the next cycle's encoding z_{k+1} and feeds it back)
    + multi-step rollout loss from random start cycles (mostly near 100), horizon curriculum. Scheduled sampling = fallback.
  - Losses: voltage curve, per-cycle capacity (vs observed end-of-discharge Q), z prediction; EOL MAPE from the rollout.
Watch-outs:
  - A linear time-invariant outer rollout with no input can only decay (sum of exponentials) -> no knee. Needs closed-loop
    feedback through nonlinear layers (LTI shared dynamics + nonlinear feedback).
  - In CV, voltage is held and current is the response; discharge length = capacity -> for future cycles the input must be
    the PROTOCOL (set-points + cutoffs), not the measured trace (its length leaks the answer).
  - Data today: V normalized by each cycle's own max (hides resistance growth), points evenly spaced in record index, rests
    dropped, curve always charge-then-discharge -> rebuild the inputs on real time / raw volts for this.
  - Check first: does "first cycle with discharge Q < 0.8 x nominal" in the data reproduce the EOL label JSONs?
  - Error compounding over hundreds-thousands of rollout cycles; capacity is nearly flat in cycles 1..100.

--- What the paper says (arxiv 2502.18807v7) vs the code ---
Resampling: paper only says "linear interpolation to resample both charging and discharging data to 150 points" (Sec 4.1);
  it never says along which axis. The code: evenly spaced in RECORD INDEX (np.interp over 1..n rows) -> real time per point
  varies with the logger (our dt channel restores it).
EOL: SOH = Q_k / Q_nominal, life = first cycle with SOH <= 80% (Sec 2.2; intro says "of the initial" - inconsistent).
  CALB: threshold 90% and Q0 = Q_1 (first cycle). Cells not reaching the threshold get a linearly extrapolated label.
  -> the Q-check script should expect: nominal@80% for Li-ion, Q1@90% for CALB, "no crossing" for extrapolated cells.
