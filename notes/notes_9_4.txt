2. Dataloader / training loop architecture
   - Dataset_original (data_provider/data_loader.py) is the one dataset class. Splits per
     --dataset come from hardcoded file lists in data_provider/data_split_recorder.py, not
     directory scanning.
   - Per file: reads early_cycle_threshold (100) cycles, each resampled to
     charge_discharge_length points, 3 channels [voltage/Vmax, current/nominal_capacity (C-rate),
     capacity(Qi)/nominal_capacity]. One cell -> many samples via a growing observation window:
     for i in range(seq_len, early_cycle_threshold+1), attn_mask marks cycles 1..i as real,
     rest zeroed; label is always the same fixed eol (life/RUL) for every i.
   - Prediction level: whole-cell single scalar (regression, output_num=1), NOT per-cycle.
     Intra-cycle encoding (per-cycle -> token) then inter-cycle encoding (attention/RNN over
     the L=early_cycle_threshold token sequence) then flatten+project to one number.
   - life_class/class_num=8 classification apparatus exists in the dataset but is DEAD CODE in
     run_main.py (life_class_criterion defined, never called) - actual task is pure regression,
     labels standardized via StandardScaler (train-fit), loss MSE or MAPE.
   - Masking mechanism differs by architecture: Transformers use it as an attention mask;
     RNNs (CPLSTM etc.) use lengths + pack_padded_sequence + gather at index (length-1); MLPs
     (CPMLP) ignore the mask arg entirely, rely on collate-fn zeroing.
   - vali_baseline (utils/tools.py) computes RMSE/MAE/MAPE + alpha-acc(15%,10%) pooled across
     ALL cells x ALL cutoff-i samples together (mixed observation lengths), plus seen/unseen
     split. evaluate_model.py's calculate_metrics_based_on_seen_number_of_cycles gives the
     per-exact-cycle-count breakdown (the paper's "accuracy vs cycles observed" curves).

4. Mamba plan (design discussion, not yet implemented)
   - Masking not needed for causal correctness (Mamba is unidirectional/causal like CPLSTM, so
     no future-leakage issue like attention would have) - but the same length signal is still
     needed as a GATHER INDEX (read out prediction at position i-1), because zero-padded cycles
     after position i still perturb Mamba's state (its Delta/B/C depend on input, zero isn't a
     true no-op).
   - Plan: batch size 1, token stream per cell with [start], per-cycle embeddings (flatten+linear,
     mimicking the existing intra_flatten/intra_embed "vectorize the spectrogram" pattern used by
     CPTransformer/CPLSTM/CPMLP), [next_cycle] between cycles, [predict] special token read out at
     the end -> single continuous scalar (linear regression head, NOT classification - confirmed
     the real task is regression to stay comparable w/ existing RMSE/MAE/MAPE/alpha-acc stack).
   - Natural augmentation: can randomly sample cutoff point per epoch (cheaper than materializing
     every cutoff like Dataset_original does) for train; use exhaustive/deterministic cutoffs for
     val/test so pooled metrics stay comparable to the benchmark's sample counts.
